# W10 预习 · Function Calling / MCP / 普通 API 调用

## 一、三句话辨析

1. **Function Calling 是模型侧机制**：模型在生成回答时「举手」说「我要调 `calc`，参数是 `35*24`」，但它只说不做——执行、校验、把结果回喂，全在你的代码里。
   判断依据：把 `TOOLS` 字典清空，模型照样能吐出那段 JSON，只是没人接。
2. **MCP 是工具侧协议**：它规定「工具怎么描述、怎么调、结果怎么回」，让工具跑在别的进程或机器上，客户端按同一套格式去连。
   它解决的是工具的**供给方式**，不碰模型怎么决定——换不换 MCP，模型那一半的活是一样的。
3. **普通 API 调用是程序侧写死**：什么时候调、调谁、传什么，都在代码的 `if` / `for` 里，模型不参与决策。
   判断依据：同一段代码跑一百次，请求序列完全一样；而前两者的请求序列每次都不同。

一句话记住三者的**决策权归属**：**模型决定 / 协议搬运 / 程序员决定**。

## 二、对照表

| 维度 | Function Calling | MCP | 普通 API 调用 |
|---|---|---|---|
| 谁做决定 | 模型（生成时决定调谁、传什么） | 不决定，只负责把工具送到模型面前 | 程序员（代码里写死） |
| 谁执行 | 你的代码里的函数 | 外部进程 / 另一台机器上的 server | 对方服务 |
| 接口长什么样 | 各家格式不同（`tool/args`、`name/arguments`…） | 一套标准：`tools/list`、`tools/call` | 各家 REST 文档，自己读 |
| 换模型要改什么 | 可能要改格式适配 | 不用改 | 不用改 |
| 换工具要改什么 | 改 `TOOLS` 字典 + `SYS` | 改一个 server 配置 | 改代码 |
| 出问题先查哪 | 提示词、解析层（本周的 `parse_calls`） | 连接、鉴权、server 是否在跑 | 网络、参数、对方服务状态 |
| 一个类比 | 客人点菜 | 餐厅之间的统一外卖标准 | 自己跑腿去买 |

## 三、拿本周的代码对照一遍

今天的 `tool_agent.py` 里，三样东西其实一一对应：

| 今天手写的 | 在 MCP 里叫什么 |
|---|---|
| `SYS` 里那段「可用工具只有这 4 个：…」 | 工具的 **schema / description**（`tools/list` 返回的东西） |
| `TOOLS` 字典 | **工具注册表**（server 端持有的工具清单） |
| `run()` 里的 for 循环 + 执行 + 回喂 | **客户端（host/client）**：收模型的调用意图、去 server 取结果、再拼回上下文 |
| `calc` / `hsk_level` / `text_difficulty` 这些函数 | **server 端的工具实现** |

所以今天这 60 行，是「私有版 Function Calling + 私有版 MCP」：模型那一半我靠提示词约定，工具那一半我靠同进程的函数调用。
W10 要做的事，就是把这两半换成标准件——工具搬到进程外，模型换一家也不用改。

有一条边界要提前分清：**MCP 不会让模型变聪明**。它只保证「工具能被发现、能被调用、结果能回来」；
选哪个工具、参数对不对，仍然是 Function Calling 那一半的事，仍然要靠提示词和工具描述去约束。

## 四、希望 MCP 帮我接上的 2 个外部工具

### 1. 本地课程目录（filesystem server，只读）

- **现在卡在哪**：`text_difficulty` 只能读 `data/` 下一个写死的目录。模型拿不到课文原文时，要么等我整段粘贴，要么猜文件名——
  今天就猜过两次（`data/愚公移山`、`愚公移山`，都不带 `.txt`），我还得在工具里补一层「看起来像文件名就当文件读」的兜底。
- **接上之后**：「这周的讲义和课文都在 W9 目录，挑一篇 HSK4 的评一下难度」——模型自己列目录、读文件、再调 `text_difficulty`，一次做完。
- **边界**：只读挂载指定目录（白名单，不给整个磁盘）；禁止写；每次读了哪个文件要能在日志里查到。

### 2. 班级成绩表（飞书 / 腾讯文档表格 server）

- **现在卡在哪**：`calc` 会算，可分数在 Excel 里。得我先复制出来、算完再贴回去——**数据靠人搬**，这一步最容易出错。
- **接上之后**：MCP 读表格 → 模型决定调 `calc` 或统计工具 → 结果写回指定 sheet 的指定区域。
- **边界**：只授权单个文档 ID，不给整个云盘；写入限定区域；写之前先 dry-run 打印「将写入 A1:F40，共 39 行」，确认后才落盘。
- 这也是 W8 愿望清单里 14 个人想要的「算分」的完整形态：真正的痛点是**数据不用人搬**，不是算得更快。
