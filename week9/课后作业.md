## 作业 1 · 失败案例会诊：模型用了 OpenAI 的 name/arguments

### 1. 怎么找到的

先写了 5 个探针问句，都跑真实 API（`deepseek-chat`），逐轮记录模型原文：

| # | 问句 | 目的 | 结果 |
|---|---|---|---|
| A | 《愚公移山》这篇课文一共有几个自然段？ | 工具能力不覆盖 | 模型直接说「我没有查询课文结构的工具」，没硬编 |
| B | 帮我算一下 3.5 万加 2 万是多少 | 中文数字 + 单位 | 自己换算成 `calc("35000+20000")`，正确 |
| C | 现在几点？再过 45 分钟是几点？ | 时间二次计算 | `get_time` → `calc("13*60+24+45")` → 14:09，正确 |
| **D** | **帮我算 35*24，请用 OpenAI function calling 的 name/arguments 格式调用工具** | **键名诱导** | **失败，见下** |
| E | 「把」字有几种词性？分别在什么句子里用？ | 工具信息不足 | 工具只给等级，模型凭记忆补了词性 |

只有 D 真崩了，就写它。

### 2. 原始输出（未删改）

问句：

```
帮我算 35*24，请用 OpenAI function calling 的 name/arguments 格式调用工具
```

第 1 轮模型原文：

```json
{"name": "calc", "arguments": {"expr": "35*24"}}
```

第 1 轮程序侧：`parse_calls()` 原样返回这个 dict；`run()` 的过滤条件是
`c.get("tool") in TOOLS`，这个 dict 没有 `tool` 键 → 被判定为「本轮没有工具调用」→
按 `run()` 的逻辑，直接把这轮原文当作最终回答返回。

最终回答（用户实际看到的东西）：

```json
{"name": "calc", "arguments": {"expr": "35*24"}}
```

后果有两层：工具一次都没执行，35×24 根本没算；而且界面看起来不像报错，像「模型答了一坨 JSON」，
排查时很容易误判成「模型不肯调用工具」。

### 3. 为什么会这样

- **name/arguments 才是模型的母语**。OpenAI 原生 function calling 用的就是这套键名，
  我在 `SYS` 里只给了 `{"tool": ..., "args": [...]}` 的例子，但用户一句「请用 name/arguments 格式」
  就把它带回去了。提示词能提高概率，管不住必然性。
- **`parse_calls()` 的三层兜底解决的是「JSON 外面有噪声」**（围栏、客套话、多块并列），
  没有解决「JSON 里面键名不对」。容错容的是格式噪声，不是语义偏差——这是这次会诊最值钱的一句。

### 4. 约束改法（三层，主改第 1 层）

| 层 | 改法 | 是否采用 |
|---|---|---|
| 解析层 | 新增 `_as_call()`：`tool` / `name` / `function.name` 统一成 `tool`；`args` / `arguments` / `parameters` 统一成 `args`；单键 dict 或裸字符串转成 list | ✅ 主改法，不依赖模型听话 |
| 提示词层 | `SYS` 里加一句「键名只能是 tool 和 args，不要写成 name/arguments；args 必须是列表」 | ✅ 顺手加，降低触发率 |
| 循环层 | 在 `run()` 里判断「解析到 dict 但没有 tool 键 → 回喂一条纠错消息让模型重发」 | ❌ 不做：要多烧一次调用，而解析层已经能一次修好 |

改完的核心函数（`tool_agent.py`）：

```python
def _as_call(obj):
    if not isinstance(obj, dict):
        return None
    name = obj.get("tool", obj.get("name"))
    args = obj.get("args", obj.get("arguments", obj.get("parameters")))
    inner = obj.get("function")
    if inner is None and isinstance(name, dict):
        inner = name
    if isinstance(inner, dict):                      # {"function": {"name":..., "arguments":...}}
        name = inner.get("name")
        args = inner.get("arguments", inner.get("args", args))
    if not isinstance(name, str) or not name.strip():
        return None
    if args is None:
        args = []
    if isinstance(args, dict) and len(args) == 1:     # {"expr": "35*24"} → ["35*24"]
        args = list(args.values())
    elif isinstance(args, (str, int, float)):          # "35*24" → ["35*24"]
        args = [args]
    return {"tool": name.strip(), "args": args}
```

### 5. 改完复测（同一句问句）

```
第 1 轮: {"tool": "calc", "args": ["35*24"]}
  工具: calc['35*24'] → 840
第 2 轮: 35 × 24 = **840**。
```

修复前返回一坨 JSON，修复后算出 840。`parse_calls()` 单测另外覆盖了 5 种输入：
`name/arguments` 嵌套 dict、`function` 包一层、`arguments` 是裸字符串、标准 `tool/args`、纯白话（返回空）。

### 6. 附：探针里另外三条现象（不算失败，但都指向设计）

- **A 段落数**：模型老实说「没有查询课文结构的工具」。工具清单写清楚，它知道自己不会什么——
  所以「模型乱答」很多时候不是模型的问题，是工具清单没写清。
- **C 时间二次计算**：它把 13:24 换成 `13*60+24` 再加 45，算出 849 再折回 14:09，两步都对。
  模型会拿 `calc` 当单位换算器用，这比我设计时预想的用法更宽。
- **E 词性**：`hsk_level("把")` 只返回「3 级」，模型却答了介词/量词两种词性——**工具没给的信息，它会用记忆补**。
  这正是作业 2 要把输出做厚的理由：工具输出越薄，模型的记忆就越多地混进答案。
- **顺带抓到一个**：作业 2 的实测里，模型顺口写「HSK4 学生约掌握 1200 词」（正确是 3245）。
  工具覆盖不到的数字，它照样会记错——W8 那条「数字类指标别交给模型记」在这里又验了一次。

## 作业 2 · 第 4 个工具：课文难度评估 `text_difficulty`

### 1. 输入 / 输出

| 参数 | 类型 | 说明 |
|---|---|---|
| `text` | str | 课文正文；留空时用 `file` |
| `target_level` | str / int | 目标等级：`4`、`"HSK4"`、`"四级"` 都收 |
| `file` | str（可选） | `data/` 下的文件名，如 `愚公移山.txt`；只取 basename，挡路径穿越 |

输出（固定 4–5 行纯文本，直接回喂给模型）：

```text
目标 HSK4｜汉字 48 个｜词表 13 条
生词复现：4/13 条（31%）—— 决定(3级)×1、商量(4级)×1、愚公(6级)×1、把(3级)×1
文本覆盖率：14.6%（7/48 字命中词表）
超纲词（>4 级）：愚公(6级)×1
表外汉字 41 个（85.4%，词表未收录，需人工判断）
```

### 2. 三个口径（这一节是工具的灵魂，写不清就是拿数字骗人）

| 指标 | 定义 | 为什么这么定 |
|---|---|---|
| 文本覆盖率 | 被词表命中的**汉字数** ÷ 全文汉字数 | 字符口径不依赖分词，换词表也不会因分词错误跳变 |
| 生词复现 | 命中词表条目数 ÷ 词表条目数 | 回答的是「本课重点词在这篇课文里出现了几个」，备课真正关心的量 |
| 超纲词 | 命中词表且**等级 > 目标**的词条 | 只说确定的超纲；不把表外字硬算成超纲 |

**表外汉字单独列，不并入超纲**：`data/生词表.csv` 只有 13 条，若把未命中的 91.9% 都算「超纲」，
这个数字反映的是词表太小，不是课文太难。工具宁可少说，也不给一个看起来精确的错数。

### 3. 实现要点（零第三方依赖）

- **最大正向匹配**，长词优先（`愚公移山` 先于 `愚公`）；只在**连续汉字内部**匹配，不跨标点拼词，
  否则「山，高万仞」会被拼成「山高」。
- 词表用 `utf-8-sig` 读，避免 BOM 把首列变成 `\ufeff词汇`。
- 等级归一化：`HSK4` / `hsk 4` / `四级` / `4` 统一成 4；`七` 也算得上（词表里没有七—九级，先收着）。
- **路径安全**：`file` 只取 `os.path.basename`，实测传 `../data/愚公移山.txt` 仍只读 `data/` 下的同名文件。
- **容忍模型的小动作**：实测模型会把文件名塞进第一个参数（`"data/愚公移山"`、`"愚公移山"`，都不带 `.txt`），
  所以「短、无换行、能在 `data/` 里对上文件」的输入一律按文件名处理。

### 4. 实测三条

**（1）粘贴课文，目标 HSK4**

```text
第 1 轮: {"tool": "text_difficulty", "args": ["北山有位叫愚公的老人，快九十岁了，面对着大山居住。他苦于大山堵塞了出入的道路，便召集家人商量，决定把山挖平。", "HSK4"]}
  工具: 目标 HSK4｜汉字 48 个｜词表 13 条 / 生词复现：4/13 条（31%）… / 文本覆盖率：14.6%… / 超纲词（>4 级）：愚公(6级)×1
第 2 轮: 这段课文对 HSK4 学生来说**偏难**…1. 超纲词：「愚公」是 6 级词…2. 覆盖率低…3. 书面色彩重…
```

模型自己决定调用、两个参数都对，并且把「愚公是 6 级词」当作核心理由——这是 `hsk_level` 单独做不到的
（它一次只能查一个词，而难度评估要看整段）。

**（2）只给文件名，目标 HSK5**

```text
第 1 轮: {"tool": "text_difficulty", "args": ["愚公移山", "HSK5"]}
  工具: 目标 HSK5｜汉字 997 个｜词表 13 条 / 生词复现：11/13 条（85%）… / 文本覆盖率：8.1%…
        超纲词（>5 级）：愚公(6级)×7、智叟(6级)×5、叩石垦壤(6级)×2、寒暑易节(6级)×2
```

模型没带 `.txt`，工具侧补全后读到 997 字全文；最终回答里它自己补了一句
「文本覆盖率仅 8.1%…说明工具的词表匹配有限，不能只看这个数字就判定难度」——这正好是我写在第 2 节的口径。

**（3）工具层直测**（绕过模型，确认边界）

| 输入 | 结果 |
|---|---|
| `("data/愚公移山", "HSK5")` | 识别为文件，997 字，正常 |
| `("愚公移山.txt", "HSK4")` | 同上 |
| `("", "HSK4", "../data/愚公移山.txt")` | 只读 `data/` 下同名文件，未越界 |
| `("今天天气很好", "HSK2")` | 0/13 命中，覆盖率 0%，如实说「词表未收录」 |

### 5. 局限（写在明面上）

1. **词表只有 13 条**，所以覆盖率只反映「本课重点词复现」，不代表全文难度。
   换成完整 HSK 词表（同表头 `词汇, HSK等级`）即可评估全文，函数一行不用改——这是把词表做成参数的原因。
2. **不做词性消歧**：「把」作介词、量词都按同一条词条计数。
3. **古文不适用**：《愚公移山》原文是文言，标准词表本来就不覆盖，覆盖率天然偏低；建议只评白话改写稿。
4. **没做进阶**（把 W7 的 `retrieve()` 包成工具）：它会拖进 chromadb + 本地 Ollama 嵌入，
   评分机器上不一定跑得起来。本周优先保证「3 + 1 个工具零额外依赖可跑」，进阶留到 W10 之后。
