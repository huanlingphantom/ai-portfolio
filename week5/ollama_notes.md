## 0. 先看这台机器（选型的唯一依据）

| 项目 | 实测值 | 对选型的影响 |
|---|---|---|
| CPU | Intel Core i5-1135G7（Tiger Lake，4 核 8 线程） | 只能 CPU 推理，速度按"每秒几十个 token"预期 |
| 内存 | **15.7 GB 总量，可用仅 2.4 GB**（负载 84%） | 按总量该上 4b，按**可用**只能上 1.5b |
| 显卡 | Intel Iris Xe 核显（无独显 / 无 CUDA） | Ollama 日志写的是 `inference compute id=cpu library=cpu`，**没走 GPU** |
| C 盘剩余 | 32 GB | 1.5 GB 安装包 + 1.4 GB 模型，够 |

关键教训：**选模型看的是"可用内存"，不是"总内存"。** 讲义说 16 GB 上 4b，那是假设这台机器是干净的；我这台开着浏览器和 IDE，实际可用只有 2.4 GB。

## 2. 我选的模型与理由

**主用：`qwen2.5:1.5b`（Q4_K_M 量化，986 MB）**
**对照：`qwen2.5:0.5b`（397 MB）**

理由按重要性排：

1. **内存卡死上限。** 4b 的 Q4_K_M 权重约 2.5 GB，加上 4K 上下文的 KV cache 要 2.8 GB 左右；我这台机器**可用只有 2.4 GB**，装 4b 必然溢到页面文件，生成速度会从"慢"变成"卡死"。讲义的原则是"内存不足就换更小的量化档"，这里直接换更小的参数档。
2. **1.5b 是这台机器的甜点。** 权重 986 MB，实测跑起来内存还有余量，速度 27–30 tok/s（一道教学题 3.5–19.5 秒答完），属于"能等"的范围。
3. **0.5b 只用来证明"能跑 ≠ 能用"。** 它 55–59 tok/s，快是真快，但第 2 题它把"把字句"说成"英语中的一个短语"——这种错误在教学设计里是灾难。留着它当反例，正好说明为什么不能只看"跑得动"。
4. **量化档怎么读：** `qwen2.5:1.5b` 默认标签就是 Q4_K_M（4 bit，K-quant，Medium），是"体积/质量"折中最常见的一档；要再省内存可以找 `q4_0` 或 `q3_K_M`，要质量可以 `q8_0`（体积翻倍，这台机器扛不住）。

## 3. 本地 vs 云端对比表（同一组 5 问）

题目固定 5 个，全部取自华文教学真实场景，且**都能人工判对错**：

1. 给《愚公移山》出 3 道 HSK4 阅读理解题，每题 4 个选项，并给出答案
2. 解释「把字句」的构成条件，并举 3 个例句
3. 把「教学目标：掌握把字句」扩写成一份 45 分钟教案的提纲
4. 学生作文里写「我把一本书买了」，错在哪里？应该怎么改？
5. 用「愚公移山」这个成语的比喻义，造 2 个 HSK4 水平的句子

生成参数统一：`temperature=0.7`、`num_predict=512`。
同一次会话里各跑一遍（本地 `qwen2.5:1.5b` vs 云端 `gemma4:cloud`，账号 `plan=free`）。

| # | 学科问题 | 本地速度（1.5b） | 本地质量 | 云端速度（gemma4:cloud） | 云端质量 | 隐私判断 | 该用哪个 |
|---|---|---|---|---|---|---|---|
| 1 | 愚公移山 3 道 HSK4 阅读题 | 7.61 s / 21 tok/s | **直接拒答**："我不能提供带有答案的阅读理解题目"（另一次跑则给出选择题但答案标错，见 3.3） | 4.58 s / 512 tok（≈112 tok/s） | ✔ 3 题 × 4 选项齐全，答案 C / A / D 与原文一致，还附了解析 | 课文是公开教材，**不敏感** | **云端** |
| 2 | 解释把字句 + 3 例句 | 12.64 s / 24 tok/s | **知识性错误**：说把字句"表示动作的被动性质"、结构是"把+动词+宾语" | 3.74 s / 512 tok（≈137 tok/s） | ✔ 四点全对：处置义、宾语必须定指、动词要有处置性、动词后必须有其他成分 | 通用语法知识，**不敏感** | **云端** |
| 3 | 45 分钟教案提纲 | 19.51 s / 25 tok/s | **结构可用、内容空**：有导入/讲解/练习/总结，但没有时间分配、没有 HSK4 的语法分级 | 3.18 s / 512 tok（≈161 tok/s） | ✔ 导入 5 分钟→结构 10 分钟→…，目标拆成"理解→掌握→辨析→运用"，可直接改成课件 | 若含本校学情、学生姓名，**敏感** | 云端出稿 → **本地脱敏改写** |
| 4 | 「我把一本书买了」错在哪 | 8.09 s / 27 tok/s | **完全没答到**：反复说这个句子是正确的，最后把问题归给"你认为的错误" | 3.51 s / 512 tok（≈146 tok/s） | ✔ 判定错、给了两种改法（改陈述句 / 补结果补语）。**但主因归错**：它说是"缺结果补语"，真正的硬约束是"一本书"**不定指**（它自己在第 2 题答对了这条，第 4 题没串起来） | **学生作文原句，敏感** | **本地**（脱敏后再上云） |
| 5 | 用愚公移山比喻义造 2 句 | 4.70 s / 25 tok/s | **半对**：句子通顺、也提到坚持，但没用上"移山"这个喻体 | 3.10 s / 227 tok（≈73 tok/s） | ✔ 两句都用上比喻义，词汇控制在 HSK4（目标、坚持、困难、成功） | 造句练习，**不敏感** | **云端** |

> 云端 token 速度是从"输出 token ÷ 墙钟"估的：云端服务不回传 `eval_duration`，所以拿不到精确值。
> 另外 Q1–Q4 的云端输出都正好卡在 512（`num_predict` 上限），说明答案被截断了——真实使用要把上限调到 1024 以上。

### 3.1 同一组问题在 0.5b 上的表现（"先小后大"的第一档）

| # | 0.5b 速度 | 0.5b 质量（对照） |
|---|---|---|
| 1 | 4.41 s / 59 tok/s | 要求"选择题"，产出的是填空题，三道题的题干还是同一句复制粘贴 |
| 2 | 4.32 s / 55 tok/s | 说"把字句是**英语中**的一个短语"，三个例句全不是把字句 |
| 3 | 5.26 s / 55 tok/s | 教案模板像模像样，但没有一个 HSK4 的具体语法点 |
| 4 | 4.76 s / 55 tok/s | 绕了一大圈，结论是"如果你需要，可以把'我'改成'他/她'" |
| 5 | 1.05 s / 57 tok/s | 只解释了成语，**一句都没造** |

### 3.2 这张表说明了什么

1. **差距不在速度，在"知识准确度"。** 本地 1.5b 一道题 5–20 秒，云端 3–5 秒——云端快 3–5 倍，但真正决定能不能用的是：本地把把字句说成被动句，云端把"定指宾语"讲对了。
2. **隐私题要分清"哪一类"敏感。** 第 4 题是学生作文原句，属于学生个人信息，**不该出机器**；第 1、2、5 题是公开教材和通用语法，本来就没有隐私负担。
3. **本地模型现在的正确定位：** 脱敏后的草稿、批量改写、离线应急（断网 / 机房无网），而不是"直接产出可上课的教案"。
4. **云端也不是全对。** 第 4 题它把"缺结果补语"当主因，漏掉"一本书不定指"这条硬约束——所以"云端出稿 + 老师终审"仍是必须的。

### 3.3 一个必须记下来的现象：同一题两次跑，结果不一样

第 1 题在 `temperature=0.7` 下跑了两轮：

- 第一轮：给了 3 道选择题，但第 1 题答案标 **D「愚公独自把山搬走了」**（原文是他带子孙一起挖）——错。
- 第二轮：直接**拒答**，"我不能提供带有答案的阅读理解题目"。

**同一个提示词、同一个模型，一次瞎答、一次拒答。** 这比"答错"更能说明小模型的不可靠：它没有稳定的能力边界，你没法靠"多试几次"来保证质量。教学材料一旦用错，是要发给学生的。

## 4. 术语正名：量化 ≠ MCP

这两个词都常在"让模型跑起来"的语境里出现，但完全不是一回事：

| | 量化（Quantization） | MCP（Model Context Protocol） |
|---|---|---|
| 解决什么 | 模型**太大装不进内存** | 模型**够不着外部世界**（文件、数据库、日历） |
| 怎么做 | 把权重从 16 bit 压到 8/4 bit，体积降到 1/4，代价是精度略降 | 定一套标准协议，让模型按统一格式调用外部工具/数据源 |
| 我这台机器上的例子 | `qwen2.5:1.5b` 的 **Q4_K_M** 就是 4 bit 量化：原始 FP16 约 3 GB，量化后 986 MB | 本周完全没用到；第 10 周专讲 |
| 一句话 | **让模型变小** | **让模型长手** |

所以"我把模型量化了，它就能读我的 Excel 了"是错的——量化只改体积，不增加任何能力；要读 Excel 得靠工具调用（MCP 或普通函数调用）。

## 5. 排错记录

### 5.1 安装包下载：GitHub 先给速度、再掐连接

- **现象**：直连 `github.com/.../OllamaSetup.exe` 一开始 269 KB/s，下到 ~116 MB 后速度掉到 **14 KB/s**，最后新连接直接 `WinError 10060` 超时。连接不断，只是"滴水"。
- **诊断**：拿不同偏移量发 Range 请求复测，全部超时；同时 `registry.ollama.ai` 能跑 3 MB/s → 不是本机网络坏了，是这条线路对 GitHub Release 的限速/阻断。
- **解决**：测了 9 个加速镜像，只有 `gh-proxy.com` 可用（187–366 KB/s），其余要么 DNS 失败、要么证书错、要么超时。改成 **4 段并行 + 每段追加写 + 速率看门狗**（20 秒内不到 80 KB 就判假连接、换源重试），后期冲到 **4.6 MB/s**，80 分钟下完 1.4 GB。
- **顺手记下的镜像实测**：`gh-proxy.com` 187 KB/s ✅ / `ghproxy.net` 9 KB/s / 直连 14 KB/s / `ghfast.top`、`ghp.ci`、`github.moeyy.xyz` 域名解析失败 / `ghproxy.cc` 证书不匹配。

### 5.2 第一版下载器把文件"撑满"了，SHA256 对不上（最坑的一次）

- **现象**：文件字节数 1,584,629,376 完全正确，但 SHA256 是 `560C318D…`，官方是 `933794ee…`；`Get-AuthenticodeSignature` 报 `NotSigned`。
- **原因**：第一版用 `truncate(TOTAL)` 先占位，然后用 `os.path.getsize()` 判断"下到哪了"。进程被 kill 后文件已经是满尺寸，重启时误判"全部完成"，中间的洞全是 0。
- **解决**：**永远不要用文件大小判断下载进度**。改成 ①分片 JSON 清单记录"哪几片真下完了"；②下载完必须比对官方 SHA256；③签名状态作为第二道校验。三条都过才安装。

### 5.3 `requests` 连不上 `localhost:11434`

- **现象**：`ConnectionError` / 代理返回 502。
- **原因**：本机 `HTTP_PROXY=http://127.0.0.1:60869`，`requests` 默认读环境变量，把 `localhost` 也送去代理了。
- **解决**：`s = requests.Session(); s.trust_env = False`。`compare_local_vs_cloud.py` 里已经写死这一行（讲义第八节同一个坑）。

### 5.4 `ollama` 服务没起来

- **现象**：`Warning: could not connect to a running Ollama instance`，随后 `Error: timed out waiting for server to start`。
- **解决**：显式 `ollama serve`，看到 `Listening on 127.0.0.1:11434` 再跑脚本。开机自启没配上不影响使用。

### 5.5 重定向 `ollama run` 的输出是乱码

- **现象**：`ollama run qwen2.5:0.5b "..." > out.txt`，文件里是 `鎶�瀛�鍙�` 这种乱码加一堆 `[?25l` 转义符。
- **原因**：Ollama 往控制台按当前代码页（GBK）写，重定向后编码就对不上了；进度条还带 ANSI 转义。
- **解决**：要拿干净文本就走 API（`/api/chat` 返回 UTF-8 JSON），或者先 `chcp 65001`。本记录里的数据全部走 API 采集。

### 5.6 内存不够怎么办

- **现象**：`ollama serve` 日志里 `total="15.7 GiB" available="2.7 GiB"`，`inference compute` 只有 cpu。
- **处理**：不上 4b，降到 1.5b；如果还要更省，`qwen2.5:0.5b` 或 `q4_0` 量化档。真要上 4b，先把浏览器/IDE 关掉腾出 4 GB 以上，否则会一直吃页面文件。

### 5.7 云端一直 401：`signin` 在浏览器里"成功了"，机器却没授权

- **现象**：`ollama signin` 走完浏览器流程，但请求云端模型仍然 `{"error":"Unauthorized"}`；重启服务也没用。
- **关键一步：先看服务自己怎么说**。`POST /api/me`（不是 GET，GET 会 405）：
  ```json
  {"error":"unauthorized",
   "signin_url":"https://ollama.com/connect?name=AIPC&key=c3NoLWVk..."}
  ```
- **原因**：`~/.ollama/id_ed25519` 的时间戳还是安装那天（10-19 17:39），说明那次 signin 没有把授权结果写回来。Ollama 云用的是**本机私钥签名**，浏览器那一步只是把公钥挂到账号下；如果中间断了（代理、浏览器没回到本地回调），就会"浏览器显示成功、机器还是未授权"。
- **解决**：直接打开 `/api/me` 返回的那个 `signin_url`，登录后点 **Connect**，看到 connected 就好；不用重跑整条 signin。
- **验证**：
  ```powershell
  # 一条命令确认到底通没通
  curl.exe -s -X POST http://127.0.0.1:11434/api/me -d "{}"
  # 期望：{"id":"...","email":"...","plan":"free"}
  ```

## 7. 课后思考题（讲义第十二节，下课前抽查）

**1. 你的机器多大内存？按选型原则能跑的最大模型是哪个？为什么不是更大的？**

15.7 GB 总量，但实测可用只有 2.4 GB（开着浏览器和 IDE）。按讲义表"16 GB → 4b(Q4)"，
4b 的 Q4_K_M 权重约 2.5 GB，加 4K 上下文的 KV cache 要 2.8 GB 左右——**比可用内存还多**，
一加载就开始换页，速度会从"慢"变成"卡死"。所以这台机器稳妥的上限是 **1.5b（986 MB）**；
想上 4b，前提是先关掉别的程序、腾出 4 GB 以上。

**2. 批改全班 40 篇含姓名的作文，用本地还是云端？必须上云要先做什么？**

**本地。** 作文里可能有真名、班级、家庭情况，属于未成年人个人信息，出机器就是数据事故。
如果非上云不可（比如要更强的批改质量），先脱敏再传：姓名换成编号（S01、S02…）、删掉学号与班级、
删掉能定位到人的细节（"我爸爸在县医院"这类），只留作文正文；批完把编号映射表留在本地、用完即删。

**3. 同一题本地答偏、云端答对，除了"模型大"还有什么因素？**

四个都实测过：

- **量化档**：本机 1.5b 是 Q4_K_M（4 bit），同样的权重用 Q8 会大一半、质量更好；
- **上下文长度**：默认 `num_ctx=4096`，长课文会被悄悄截断，模型只能瞎猜；
- **提示词写法**：不给格式约束（"每题 4 个选项、答案另起一行"）时，小模型更容易跑偏；
- **`max_tokens`**：截断不报错。实测 `max_tokens=40` 时答案断在"本在冀之南，河之南，"；
- 另外 **temperature**：默认 0.7 对教学材料偏高，出题建议 0.2–0.3。

## 8. 课后作业（下周四前）

### 作业 1｜读 Ollama 官方文档，记 3 条以前不知道的用法

1. **Modelfile 把参数固化进模型**
   ```dockerfile
   FROM qwen2.5:1.5b
   PARAMETER temperature 0.3
   SYSTEM 你是面向 HSK4 学习者的中文老师，回答控制在 150 字以内。
   ```
   `ollama create hsk-tutor -f Modelfile` 之后，`ollama run hsk-tutor` 就自带温度和系统提示，
   不用每次在代码里传。**换模型只改第一行。**
2. **`keep_alive` 控制模型常驻内存**（实测）
   ```json
   {"model": "qwen2.5:0.5b", "messages": [...], "keep_alive": "30m"}
   ```
   `ollama ps` 里会写 `59 seconds from now`（传 `"1m"` 时）；传 `0` 则立刻卸载，`ps` 变空。
   课堂演示前先预热一次、给 30 分钟，就不用在学生面前等首次装载的 30 秒。
3. **`format: "json"` 强制结构化输出**
   `/api/chat` 里加 `"format": "json"`，模型只吐合法 JSON。批量出题时配合"每题 4 个选项"的
   字段说明，可以直接 `json.loads`，不用正则去抠——小模型最容易在格式上翻车，这个参数能救一半。

### 作业 2｜换量级对比：质量提升值不值得多占内存

| | qwen2.5:0.5b | qwen2.5:1.5b |
|---|---|---|
| 体积 | 397 MB | 986 MB（+148%） |
| 速度 | 55–59 tok/s | 27–30 tok/s（**慢一半**） |
| 把字句 | "英语中的一个短语" | "表示被动性质，结构是把+动词+宾语"（仍错） |
| 愚公阅读题 | 填空题冒充选择题 | 有选项但答案标错 / 直接拒答 |

**判断：这次不值。** 2.5 倍磁盘、一半速度，换来的答案**仍然不能直接用**——只是从"错得离谱"
变成"错得隐蔽"。真要质量，不如把这活交给云端（W6 的双引擎就是干这个的）。

没测 4b 的原因也写清楚：权重 2.5 GB > 可用内存 2.4 GB，一定会换页，测出来的数字没有参考价值。

### 作业 3｜离线部署复盘：如果去无网的乡村学校

我会按这个顺序准备：

1. **介质**：1.51 GB 安装包 + 模型离线包（`ollama pull` 出来的 `~/.ollama/models` 可以整目录拷）
   装进 U 盘，**每个文件附一份 SHA256 清单**。这次下安装包就吃过亏：文件大小一模一样、内容是坏的，
   靠哈希才发现。乡村没有第二次下载机会，校验清单是必需品。
2. **模型定档**：教室机器大概率 8 GB 内存 → 只带 0.5b/1.5b 两档，先跑通 0.5b 建立手感。
   带 4b 是给自己找麻烦（首次装载要等，内存一紧就卡）。
3. **内存预算**：系统留 1 GB，1.5b 常驻约 1 GB，同时只挂一个模型；代码里 `keep_alive=0`，
   用完立刻释放，别让它在后台待着。
4. **断网演练**：装完拔网线跑 `ollama run`，再跑一遍 `compare_local_vs_cloud.py`，
   确认所有请求都打到 `127.0.0.1`——离线部署最容易翻车的地方，是某个环节偷偷在等网络。
5. **教学取舍**：离线只做"格式固定、可人工校验"的活（出题、改错、列提纲）；
   要质量的备课（教案、长文改写）在有网时提前做好带过去。

一句话：**离线部署的难点不是装，是"没有第二次机会"**——所以介质要校验、模型要保守、流程要演练。
