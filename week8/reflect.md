# 作业 4 · 官方 RAG 对照：一个改造点 + 300 字反思（B 路径）

**分工说明**：5 行流水线映射表见 `RAG流水线映射表.md`（全员最低要求）。我走 **B 路径**——没有跑官方示例（本机 16G 内存但官方示例要 OpenAI 嵌入 + `deepagents` beta 包，装下来与本周主线无益），只读了官方 RAG 文档与 llm-universe C3/C4，然后拿自己的 `rag_qa.py` 做了一处改造。许可证上留意：llm-universe 未附 LICENSE，按默认保留所有权利，我只读思路、没有复制代码。

## 改造点：给每个分块补"章节抬头"

官方教程的 `RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=200)` 只保证"按长度切、边界尽量落在段落上"；我的语料是《等级标准节选》，最要命的一块是"一、语言量化指标总表"——整整 7 列数字，切完以后单独一块里只有 `初等 一级 269 300 500 42` 这样的裸数字，检索时几乎不可能被"HSK4 词汇量是多少"命中。

改法是在 `split_documents()` 之后加一层 `_add_heading_context()`：每块前面补一行 `【一、语言量化指标总表（音节 / 汉字 / 词汇 / 语法）】`，如果块内没有标题，就往前回溯最近的 `^[一二三四五六七八九十]+、` 标题。这样做没动 loader、没动 embedding、没动 Chroma——正好印证官方那句"组件可替换，应用逻辑不动"。效果是那张总表从"排最后"进到 top-3，1.5b 才抄得出 `1000/3245`。

## 300 字反思

对照下来最扎心的一点：官方文档不是"一份教程"，而是一组模式——同一页里 2-Step、Skills-guided、Rubric-checked、Retrieve-offload-delegate 并列，默认实现反而是最复杂的那种（把检索结果卸到文件系统、再分派子 agent 读）。我原本以为"官方 = 标准答案"，读完才发现它给的是"按场景选型"：2-Step 简单、延迟低、调用次数有上限，适合 FAQ 和文档机器人；代价是检索原文全进上下文，长语料下模型会迷失。我的 v1.0 是标准 2-Step，所以"三问里有两问答不上"不是实现错了，是模式本身的边界——语料只覆盖词汇量指标，问把字句教学法就该拒答。

第二个收获是评估。llm-universe 把生成评估与检索评估分开做，我此前只有一张"裸答 vs RAG"的对照表，混在一起看不出问题出在哪一步。改造抬头之后我才分清：Q2 答错是**检索**没把表捞上来，Q1 答"未提及"是**语料**里真没有。这一步分开，才知道下一次该调 chunk 还是该补语料。

第三，许可证这课很具体：官方文档注明出处即可引用，llm-universe 无 LICENSE 就只能读思路。开源不等于无规则，写进 README 的借鉴来源不是形式，是边界。
