# 作业 2 · README 里「已知问题」为什么要诚实写（200 字）

因为 README 的读者不是写代码的人，是"下一个要跑它的人"。功能段写的是承诺，已知问题写的是边界；只写承诺，等于把排雷的活留给别人。

这次做 v1.0 有具体例子：本地 `qwen2.5:0.5b` 读不懂四列数字表，问"HSK4 词汇量"会回"资料中未提及"；而云端能答"新增 1000、累计 3245"。如果我把这条藏起来，邻座照 README 装完 0.5b，第一次演示就翻车，还会怀疑是自己装错了。写进去，他直接改成 1.5b 或 `prefer="api"`，三十秒解决。

诚实写限制还有一层：它逼我说清"我的系统在哪儿不算数"。语料只有一份等级标准节选，问把字句教学法本来就该拒答——把这条写明白，比假装什么都会更专业。藏着的限制迟早会在别人机器上爆炸，写出来的限制只是一个待办。
