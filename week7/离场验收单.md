## 2. 生成环节复用了 llm.ask()

```python
def rag_qa(question, prefer="local", k=3, rebuild=False):
    from llm import LLM          # week06 的模块，靠 weekpath 才能 import 到
    llm = LLM()
    ctx = retrieve(question, k=k, rebuild=rebuild)
    return llm.ask(build_prompt(question, ctx), prefer=prefer)
```

没有新写一套 `requests.post(... /chat/completions)`。证据是运行日志里那行 `[耗时/费用]`——
**它是 `week06_双引擎/llm.py` 自己打的**，说明请求确实从那里出去：

```
[耗时/费用] 实际引擎=local 模型=qwen2.5:1.5b 用时 8.75s 输出 21 tokens 费用 0.000000 元
```

## 4. 检索相关性（不是随便 top-k）

`python week07_RAG/rag_qa.py "问题" --show` 打印每段距离（余弦距离，越小越像）：

| 问题 | top-1 距离 | top-1 是哪一段 | 可靠性 |
|---|---|---|---|
| 中等阶段·词语 | 0.6462 | 三、各等次总体描述（原文就有 5456） | 好 |
| 中等阶段·语法点 | 0.6118 | 一、语言量化指标总表（数字在散文段，排第 2） | 好 |
| 中等阶段·音节 | 0.6462 | 三、各等次总体描述 | 好 |
| HSK4 词汇量 | 0.6116 | **二、HSK 对应关系（一个数字都没有）** | 差 |
| 高等阶段·汉字 | 0.6576 | 二、HSK 对应关系（总表掉到 0.7681） | 差 |

第 4、5 行的首段都**不是**含数字的那一段——这是 1.5b 读表翻车的直接原因：它拿到的 top-3 里，
真正有数的那块排第 3（1.0394 / 0.7681）。云端能把三段一起读，所以同样条件下它答对了。

**为什么给每块补抬头（`_add_heading_context()`）**：做过一次对照——同一个库，问
"四级（中等）本级新增词汇量是多少"，纯数字的总表块排到 6 块里的最后一名（距离 0.524），
因为那段向量里几乎只有数字，没有"词汇量"这种语义锚点。补上 `【一、语言量化指标总表…】` 这样一行之后，
这类问题总表能稳定进 top-3。**但抬头不是万能的**：问法里带"本级新增"这种词时，
"四、三维评价维度"（那句"应掌握音节、汉字、词汇的数量"）仍然会压在前面——
**检索质量是 语料 × 分块 × 问法 三件事一起决定的。**

## 5. 提示词

```python
def build_prompt(question, ctx):
    return ("根据以下资料回答问题，资料中没有的内容就如实说“资料中未提及”：\n"
            "%s\n\n问题：%s" % (ctx, question))
```

"资料中没有的内容就如实说"这句是讲义原文，一字未改；后面加的那句"写一行出处"是**作业 1 进阶**（答案附出处）的要求。
这句限定语在调参期确实触发过：问"一级要求掌握多少个音节"、top-3 没覆盖到"一级"那行时，
模型答的是"资料中没有提及一级的要求"——没资料时它选择不编。（那次是调试期，没进最终五组。）

顺带一个反例：第 4 组首段根本没数字，它却答 `1000/3245 = 3.104`——**说明"未提及"这句能挡住"没资料"，
挡不住"资料不对口"**。
