## 二、四个「不」（讲义第四节表格）

| 不做的事 | 为什么 | 本项目的做法 |
|---|---|---|
| 不写进代码 | 代码会进仓库、会被截图、会发给同学 | 代码里只有 `os.getenv("DEEPSEEK_API_KEY")`，密钥只在 `.env` |
| 不进截图 / 录屏 | 截图会被发到群里、写进报告 | 实录里密钥一律打码成前 4 位 |
| 不进聊天记录 | 粘贴给 AI 排错 ＝ 把密钥交出去了 | 报错贴给 AI 前，先把 `sk-…` 段打码 |
| 不进仓库 | `.env` 一旦提交，历史记录里永久留存 | `.gitignore` 含 `.env` 与 `.env.*`，且保留 `!.env.example` |

## 三、如果不小心泄露了，处置流程

1. **先吊销，再改代码**。到平台控制台把泄露的那把密钥删除／重置，生成新密钥。
   只删仓库文件是不够的——历史提交里那把密钥早就被爬虫抓走了。
2. 把新密钥填进本机 `.env`，确认程序能跑通（`python week4_API/week4_api_bot.py "测试"`）。
3. 若密钥已进过 git 历史：本地用 `git filter-repo` 或 BFG 清史，然后
   `git push --force`；或者**更省事的做法**——直接吊销密钥，让历史里那把变成废串。
4. 到平台后台核对账单，确认没有异常调用。

> 记住：密钥泄露 ＝ 别人用你的钱。公开仓库上爬密钥的机器人是分钟级的。
