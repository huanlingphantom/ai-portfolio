# W4 参数体验记录（提交物 3）

> 平台：DeepSeek `deepseek-chat`　　base_url：`https://api.deepseek.com/v1`
> 实测时间：2026-10-12 14:0x（北京时间，**高峰时段**）
> 统一问句：`用一句话说明什么是把字句`
> 每组都跑在本项目的 `week4_API/week4_api_bot.py` 上，命令见每节小标题

讲义第六节第 3 步要求「感受参数对输出发散度和长度的影响」。下面四组是实测原文，最后一列是我自己写的观察。

## 总览（讲义表 6 的填写结果）

| 参数 | 我填的值 | 观察到的现象（自己写） |
|------|----------|------------------------|
| `temperature = 0.0` | 0.0，`max_tokens=60`，同题问 3 次 | 3 次里 **2 次逐字相同**，第 3 次只差一个词（「产生某种结果」→「影响」）。输出长度 36/34/34 token，**几乎不抖**。 |
| `temperature = 1.5` | 1.5，`max_tokens=60`，同题问 3 次 | 3 次**措辞、句式、长度全不一样**（54/34/44 token）。第 3 次还自发加了 Markdown 加粗和例句「他把书读完了」。**同一问题问两遍得到两个答案**，讲义思考题 1 说的就是它。 |
| `max_tokens = 15` | 15，`temperature=0.7` | 输出被**硬截断在半句上**：`把字句是汉语中一种用介词"把"将动词的`。没有报错、没有提示，就是戛然而止——做教案时最危险的一种失败。 |
| `max_tokens = 800` | 800，`temperature=0.7` | 模型**用到 35 token 就自然收尾**，并没有凑满 800。说明 `max_tokens` 是「上限」不是「目标」。 |

## 实验 A　temperature = 0.0　（同一问题问 3 次）

```
python week04_API/week4_api_bot.py "用一句话说明什么是把字句" -t 0.0 -m 60 -n 3 --no-log
```

| 第几次 | 回答 | 输出 token | 费用 |
|---|---|---|---|
| 1 | 把字句是汉语中一种用介词“把”将动词的受事（宾语）提到动词之前，以强调对该对象进行处置或**产生某种结果**的句式。 | 36 | ￥0.000310 |
| 2 | 把字句是汉语中一种用介词“把”将动词的受事（宾语）提到动词之前，以强调对该对象进行处置或**影响**的句式。 | 34 | ￥0.000294 |
| 3 | （与第 2 次逐字相同） | 34 | ￥0.000294 |

**观察**：三次高度一致，只有第 1 次结尾用了「产生某种结果」、后两次用「影响」。
`temperature=0.0` 相当于「每次挑最可能的那个词」，所以适合**要可复现的场合**——
比如批量生成同一格式的练习、或做评测对比。三次合计 137 token，￥0.000898。

## 实验 B　temperature = 1.5　（同一问题问 3 次）

```
python week04_API/week4_api_bot.py "用一句话说明什么是把字句" -t 1.5 -m 60 -n 3 --no-log
```

| 第几次 | 回答 | 输出 token | 费用 |
|---|---|---|---|
| 1 | 把字句是指用介词“把”将动词的受事（宾语）提到动词前，构成“主语＋把＋宾语＋动词＋其他成分”结构的一种主动句句式，用来强调对人或事物加以处置、影响或产生某种结果。 | 54 | ￥0.000454 |
| 2 | 把字句是汉语中一种用介词“把”将动作的受事（宾语）提到动词之前，以强调对该对象的处置或影响结果的句式。 | 34 | ￥0.000294 |
| 3 | 把字句是指**由介词“把”引入受动对象、并将其置于动词前，用以强调对该对象施加处置或产生某种结果**的汉语句式（如“他把书读完了”）。 | 44 | ￥0.000374 |

**观察**：三次没有一句相同，连**排版习惯都变了**——第 3 次自己加了粗体和例句。
`temperature=1.5` 已经超出常规范围（一般用 0~1），出现「不按套路出牌」的输出很正常。
想让学生看到「同一个问题答案可以长得不一样」，用这个值最直观；但要**直接进教案，就得人工挑一遍**。
三次合计 165 token，￥0.001122 —— 比 A 组多用 20% 的 token，因为啰嗦的那次更长。

## 实验 C　max_tokens = 15（看截断）

```
python week04_API/week4_api_bot.py "用一句话说明什么是把字句" -t 0.7 -m 15 --no-log
```

原始输出：

```
把字句是汉语中一种用介词“把”将动词的
```

**观察**：句子被从中间切断，标点都没收，程序也不会报错（`finish_reason` 是 `length`）。
用量 `输入 11 + 输出 15 = 26 token`，￥0.000142。
**教学场景的启发**：如果程序自动生成板书或题目，`max_tokens` 太小就会产出这种半句话。
所以上线前要把 `max_tokens` 设够，并且**检查 `finish_reason` 是否为 `length`**。

## 实验 D　max_tokens = 800（看完整）

```
python week04_API/week4_api_bot.py "用一句话说明什么是把字句" -t 0.7 -m 800 --no-log
```

原始输出：

```
把字句是汉语中一种用介词“把”将动词的受事（宾语）提到动词前，以强调对受事加以处置或影响的句式。
```

**观察**：句子完整收尾后模型主动停下，**只用了 35 个输出 token**，离 800 的上限很远。
`输入 11 + 输出 35 = 46 token`，￥0.000302。
**结论**：`max_tokens` 是安全上限，不是要凑满的目标；调大不会多花钱，只在模型话多时才起作用。

## 一句话总结

| 想控制什么 | 调哪个 | 效果 |
|---|---|---|
| 结果稳不稳、能不能复现 | `temperature` | 0.0 几乎固定，1.5 每次都不同；要可复现就固定它 |
| 回答会不会被砍断 | `max_tokens` | 太小会硬截断在半句上，且**不报错**；它是上限不是目标 |
| 花多少钱 | 两者都影响 | 费用 = 输入 token × 输入单价 + 输出 token × 输出单价（本项目按 DeepSeek 官方价格页实测计价，见 `W4作业实录.md`） |
